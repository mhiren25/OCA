/opsx:propose Sanitize: identify the live instruction region within an email
thread, and segment the rest.

Output is ANNOTATIONS OVER THE ORIGINAL TEXT — labelled spans — never a
rewritten string. Rewriting invalidates the character offsets ParsedEmail
recorded, and provenance depends on those.

Segment, never delete: signatures, disclaimers, mobile footers and injected
banners are labelled, not stripped. A signature often carries the account or
the authority; and a banner like "Learn why this is important" sits exactly
where an instruction would.

Live region: handle the structural cases in code — "From:/Sent:/To:" dividers,
"On <date> X wrote:", ">" prefixes, HTML blockquote. When the boundary is
genuinely ambiguous, mark it so rather than guessing.

Bias toward INCLUSION. Excluding a live region silently drops a real client
order, which nothing downstream catches. Including history risks a phantom
order, which the reviewer sees and line-precision measures. The two errors
are not equally bad.

Paste as the proposal:

Implement extraction/extractor.py and prompt v1. One LLM call per email: input is the sanitized live region from 008 plus envelope metadata, output is a CaptureModel.

The prompt lives in a versioned module exporting PROMPT_VERSION and a content hash, both of which flow into the Exchange from 006 so a prompt change invalidates cassettes rather than replaying stale answers.

The LLM does not emit character offsets. It quotes the client's words verbatim as raw_text for each field, and code locates those quotes in the body to derive provenance — the same placement logic scripts/build_fixture.py uses for labels: anchor each order on its most distinctive value, resolve the rest by proximity. Models are unreliable at counting characters, and a plausible-but-wrong offset is worse than none because it points a reviewer at the wrong words. Factor the locator out of build_fixture.py into a shared module so the corpus and the runtime agree by construction.

Prompt rules, each of which must have a fixture behind it:

Never invent a value. If the client did not say it, the field is Unresolved. A fabricated value is the only error class gated at zero.
"Sell all" is EntirePosition, never a number. A figure in parentheses is client_asserted — the client's belief about the position — not the order quantity.
One lines[] entry per order. Never merge two orders, never drop one. Line recall is a hard 100% gate.
raw_text is quoted, never paraphrased, or the locator cannot place it.

Response is validated against corpus/schema/capture.v1.schema.json. A response that does not validate is a failure, never silently coerced.

No secret, token or client holding enters the prompt.

Out of scope: enrichment via MCP, mapping to OrderRequest, attachment text.
